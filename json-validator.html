Common JSON errors

Errors the validator catches

These are the most frequent JSON syntax errors developers encounter when working with APIs and config files.

Trailing commas
{"a": 1,} — The trailing comma after the last element is not valid in JSON (unlike JavaScript).
Unquoted keys
{name: "Alice"} — JSON requires all keys to be double-quoted strings.
Single quotes
{'name': 'Alice'} — JSON only accepts double quotes, never single quotes.
Comments
// this is a comment — JSON does not support comments. Use JSONC or strip comments before parsing.
Undefined values
{"x": undefined} — JSON has no undefined. Only null, booleans, numbers, strings, objects, arrays.
Mismatched brackets
{"a": [1, 2} — An array opened with [ must close with ], not }.

FAQ

Common questions

What is JSON validation?
JSON validation checks whether a string conforms to the JSON specification (RFC 8259). Valid JSON must use double-quoted keys, have no trailing commas, use only the six valid value types (string, number, boolean, null, object, array), and have properly matched brackets and braces.
Why does my JSON fail validation?
The most common reasons are: trailing commas (e.g. [1, 2, 3,]), unquoted property names, single quotes instead of double quotes, JavaScript comments (// or /* */), or the value undefined which doesn't exist in JSON. The validator shows the exact error message so you can locate the problem.
Is there a difference between JSON and JSONC?
Yes. JSONC (JSON with Comments) is a superset of JSON that allows // line comments and /* */ block comments. It is used by tools like VS Code settings files and TypeScript config files. Standard JSON parsers reject JSONC. This validator checks standard JSON — strip comments before pasting JSONC.
Can I validate JSON from an API response?
Yes. Copy the raw response body from your browser's DevTools Network tab, Postman, or curl, and paste it here. Since all processing is browser-based, API tokens and sensitive data in the JSON are never sent to any server.
